# Collateral Mobility Desk

A desk that lets a buy-side firm meet a variation margin (VM) call with tokenised collateral, any day and any hour, without selling assets first. CDM is the semantic layer; a ledger is the state layer.

Read `intent.md` before any work. It is the source of truth for scope. If a request falls outside it, stop and say so.

## How work flows here

Every stage commits a file the next stage reads:

`intent.md` → `spec.md` → `plan.md` → code + tests → eval results → review record → production signal → new `intent.md`

- Do not write code for anything that is not in `plan.md`.
- Do not change `intent.md` without the owner's sign-off.
- Every session verifies its own work: run the tests and evals before you say a task is done.

## Rules that are never broken

1. **CDM is used as generated by FINOS.** Never edit generated CDM types. The Desk's own additions live in `extension/`, keyed by the asset identifier.
2. **Schedules are applied as written.** CDM's `CheckEligibilityByDetails` diverges from schedule meaning in four places (see below). Never rely on it for a decision; test against it instead.
3. **Eligibility, haircut and limit maths are deterministic code.** Never let model output decide eligibility or an amount.
4. **A person approves every extracted value.** The agent proposes; nothing leaves it unapproved.
5. **The Desk verifies before it uses a schedule.** It checks approval, both SHA-256 hashes and the CDM rules. Any failure changes nothing.
6. **No client data goes to an outside AI model** unless the partner has approved it. AI features are off by default.
7. **Present mode always runs on the built-in schedule.** Demo figures must not change.
8. **Ledgers sit behind one adapter interface.** No ledger-specific code outside `desk/adapters/`.
9. **Synthetic or anonymised data only.** No real counterparty names, CSAs or holdings in the repo, prompts or fixtures.
10. **Say "CDM-aligned", never "CDM-compliant".** The Desk is not affiliated with or endorsed by ISDA or FINOS.

## Known CDM divergences (each must have a test)

FINOS source, commit 830b53b, 16 Oct 2026:

1. Exclusion rules are dropped before checking, so excluded assets are never excluded.
2. Fund type is not compared, so an ETF matches an MMF rule.
3. Period units are not converted, so a 6-month bound reads as 6 years.
4. An exclusive lower maturity bound appears to be evaluated in reverse. Confirm this with a test before raising it with FINOS.

Open items from connecting the agent and the mapper:

- **A.** "Not less than one year" means an inclusive lower bound. The spreadsheet format needs an inclusive/exclusive marker per bound.
- **B.** Index-linked exclusion: use an in-schedule exclusion rule if CDM can identify index-linked gilts. Otherwise use a flag labelled as part of the extension.
- **C.** The MMF limit is 50% of aggregate collateral, not a flat amount per delivery.

## Checks before every commit

- All tests pass in `desk/`, `mapper/` and `agent/`.
- CDM output validates against the model's rules and the `finos-cdm` Python package.
- All five FINOS sample schedules still validate.
- Divergence tests and tamper tests on the schedule export pass.

## Needs a human review before merge

- Settlement logic, or anything that moves a token or the cash leg
- How a CSA clause maps to CDM
- Any change to the four rules above about CDM, schedules, maths or approval
